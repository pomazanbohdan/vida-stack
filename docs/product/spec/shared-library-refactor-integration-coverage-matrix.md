# Shared Library Refactor Integration Coverage Matrix

Status: `in-progress`

## Summary
- Feature / change: shared-library rewrite, deduplication, and file decomposition for VIDA runtime operator surfaces.
- Owner layer: `runtime-family`
- Runtime surface: `taskflow`, `docflow`, launcher shell `vida`
- Active task: `architecture-refactor-shared-library-rewrite-gate`

## Closure Contract
- The refactor gate cannot close on code movement alone.
- Every affected file or public surface in this refactor scope must map to:
  - moved or deduplicated functionality,
  - the canonical shared boundary that now owns it,
  - integration or public-surface tests,
  - proof commands,
  - remaining defect-reconciliation decisions.
- New architecture is canonical. Do not keep legacy modes, legacy-named modules/functions, compatibility aliases, or parallel old/new execution paths unless a bounded migration task explicitly owns removal.
- Defects exposed by this matrix are fixed inside the canonical boundary immediately when they belong to the refactor scope. Older defect tasks made obsolete by those fixes must be reconciled with evidence instead of left as stale backlog.
- This gate is defect-discovery-and-elimination work, not a test inventory exercise. Each file/surface batch must use integration or public-surface tests to expose the behavior defects in that scope, fix those defects in the shared canonical boundary, and then prove the corrected behavior before the next unrelated slice.
- Downstream defect tasks become closure candidates only after the matching matrix row proves the defect is fixed or structurally obsolete. Until then they remain unresolved evidence, not assumed duplicates.

## Remaining Coverage Gaps Blocking Gate Closure

No remaining matrix-owned coverage gaps are known for `architecture-refactor-shared-library-rewrite-gate`. Stale run graph cleanup, impossible retire command, TOON/default output parity, and `--json`-biased next-action defects are either covered by the green matrix rows above or remain as separate backlog items outside this gate's bounded shared-library rewrite closure.

## Defects Found And Fixed During Matrix Execution
- `stale_missing_task_run_graph` consume-continue JSON exposed `artifact_refs.run_id` but omitted `artifact_refs.dispatch_packet_path` even when the active receipt had packet evidence. Fixed by preserving receipt-backed dispatch packet path in stale missing-task resume errors so `consume_continue_resume_error_payload` can populate artifact refs consistently.
- Runtime-binding and status-signal human next actions hardcoded `--json` in paused, closed, missing-task, open delegated cycle, ready downstream handoff, blocked run-graph, recovery-target-missing, and terminal authoritative-run guidance. Fixed string-built signals by routing command snippets through `operator_command_text::human_command` and updating tests to assert no JSON-first default guidance.
- `task import-jsonl` blocked error payload manually constructed release-1 `shared_fields` and `operator_contracts`, duplicating the canonical operator envelope builder, and its retry action recommended `--json`. Fixed by routing the payload through `build_release1_operator_output_payload` and normalizing retry command text through `operator_command_text::human_command`.
- Static status/doctor next-action constants still leaked `--json` and duplicated retrieval-trust guidance across `status_surface_signals` and `doctor_surface`. Fixed by converting them into shared string builders in `status_surface_signals`, routing doctor/status operator contracts through the shared catalog, and adding caller tests that fail on JSON-first human guidance.
- `taskflow_consume_resume.rs` had three production paths manually finalizing release-1 operator truth and assembling mirrored snapshot/output payloads. Fixed by extracting `taskflow_consume_resume_projection`, routing runtime resume/deferred/cached handoff projections through the shared builder, and proving parity through module tests plus public consume-continue smoke variants.
- `status` and `doctor` default human output used old line rendering instead of canonical compact TOON, and status dispatch compact summaries preserved `--json` in human next-action text. Fixed by adding `operator_toon_report`, routing default plain `status`/`doctor` through it, normalizing dispatch recommended commands through `operator_command_text::human_command`, and adding public default/JSON/help smoke coverage.
- `doctor_surface_contract_smoke` project-bound fixtures wrote an underspecified `vida.config.yaml`, causing boot/protocol-binding setup to fail on `role_selection.fallback_role` and `agent_system.state_owner` before the status/doctor behavior under test could run. Fixed the fixture to use the current minimal valid runtime config and proved the whole contract file.
- `task progress --basis direct-children` and `task closure-ready --basis direct-children` reported `direct_children_remaining` for non-epic parent tasks even when all direct children were closed, because direct-child closure candidacy was limited to `issue_type=epic`. Fixed direct-child semantics so any non-closed parent with all direct children closed-like is ready to close, and added a focused regression.
