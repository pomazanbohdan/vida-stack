# Product Spec Index

Purpose: provide the local entrypoint for product/spec navigation without duplicating the detailed current canon catalog.

## Routing Rule

1. Start here for product/spec orientation.
2. Use [current-spec-map.md](current-spec-map.md) for short routing decisions.
3. Use [current-spec-catalog.md](current-spec-catalog.md) for the full active artifact list.
4. Do not maintain manual document lists in this index.

## Document Roles

1. `*-law.md` documents durable product law.
2. `*-contract.md` documents bounded product/runtime contracts.
3. `*-model.md` documents current architecture or runtime models.
4. `*-spec.md` documents execution-ready implementation specifications.
5. Research-backed references belong under [../research](../research) unless promoted into current spec canon.

## Authoring Rule

1. Use [templates/feature-design-document.template.md](templates/feature-design-document.template.md) for new bounded feature/change design docs.
2. Register promoted current product/spec artifacts in [current-spec-catalog.md](current-spec-catalog.md).
3. Keep [current-spec-map.md](current-spec-map.md) short; it routes to owners and the detailed catalog.
4. Keep repository-level narrative in the root [README.md](../../../README.md), not in product/spec indexes.
5. Use [protocol-authoring-and-token-economy-law.md](protocol-authoring-and-token-economy-law.md) when writing or compressing protocols, instructions, bootstrap-visible docs, or token-heavy process law.
